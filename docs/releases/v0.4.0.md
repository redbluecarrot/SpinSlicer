# SpinSlicer v0.4.0 — Compute Modes, H.264 Export and Optional GPU / Режимы вычислений, экспорт H.264 и необязательный GPU

## English

### Read this first: projector gamma is now applied

The projector gamma of the machine profile is now **applied to the exported MP4**. In v0.3.2
the profile had a gamma field, but the export ignored it. The default is still **1.0
(linear)**, so a default profile gives the same frames as before.

- Most projectors have a gamma close to 2.2. With 1.0 the frames are sent unchanged, a mid-gray
  value shows less than half of the light it should, and **the delivered dose is no longer
  linear**. Set the projector gamma in the machine profile (ideally from a measurement, see the
  test ramp below).
- If your profile already contained a gamma other than 1.0, it takes effect now and **changes
  the exported frames and the dose** compared with v0.3.2.
- The PNG frames in the run folder and the projector tab's preview always stay linear. Gamma
  only reaches the MP4. For a gamma other than 1 the frames are encoded in floating point
  before the single 8-bit rounding and kept in `projector_frames/`.

Other changes that alter what the printer receives, compared with v0.3.2:

- The default frame rate is **30 fps** (24 before; 30 divides the 60 Hz projector refresh
  evenly). With the same number of frames the rotation speed changes (360 frames: 5 rpm instead
  of 4). Check the speed in the file name.
- The MP4 is **H.264 in full range** (black 0, white 255), not `mp4v`, and is named
  `projection_<rpm>rpm.mp4`.
- `output_res` must be **even**.

### Overview

SpinSlicer v0.4.0 adds three compute modes (Auto, Economy, Maximum) that change speed and
memory but not the frames for printing, GPU acceleration through Taichi as an optional
installer component, an H.264 export built for the printer, and a direct-projection view next
to the optimised frames.

### What's New in v0.4.0

#### 1. Export for OpenCAL

- **Full-range H.264.** Black stays 0 and white 255. In limited range the background became
  16/255 (about 6 % light all the way round) and 36 gray levels were lost. A range option
  (full 0–255 or limited 16–235) is in the projector tab; limited range is the safer choice
  for players that ignore the range flag, but a player or HDMI output that treats everything as
  full range then shows black as 16/255.
- **Full-resolution source.** The MP4 is built from the PNG files of the run, not from the
  preview, which is shrunk to 900 px. The rotation speed in the name comes from the frame count
  on disk and the manifest's frame rate, with at most two decimals. Whether OpenCAL's file-name
  parser accepts a decimal point has not been verified: prefer a frame count that gives a whole
  number of revolutions per minute.
- **Test ramp.** A button saves gray bars 0–255 (dense at both ends) with the chosen range, to
  check the whole playback chain and the projector, for example with a light meter. It is linear
  unless "With the profile gamma" is ticked, so the projector gamma can be measured from
  scratch, and it follows the last run's frame count and rate (`ramp_5rpm.mp4` for 360 frames at
  30 fps).

#### 2. Compute modes

- **Auto, Economy, Maximum.** Economy uses little memory and one thread (it does not create the
  direct projection, and says so in the log). Maximum uses every core and, with Taichi and a
  suitable graphics card, runs the optimiser on the GPU: the whole Z block stays on the device.
  Auto chooses by the machine and picks a GPU only when its memory is known (NVIDIA, through
  `nvidia-smi`); an explicit Maximum may use any Vulkan or Metal device.
- **Same frames.** Economy and Maximum frames agree to one gray level; GPU and CPU frames were
  identical in the tests. A job on a 3DBenchy (grid 256, 360 frames, 505 layers, dose window on)
  took 143 s and 0.45 GB of memory in Economy, about 50 s on 12 cores and about 17 s on an
  RTX 4060 Ti in Maximum (measured when running from source).
- The ray matrix is kept between jobs in Maximum mode and released in Economy mode.
- If the GPU cannot be used, the log says why and the job continues on the CPU; the manifest
  records what really ran (`compute.device_used`, `compute.gpu_error`).

#### 3. Optimiser and projections

- **Dose window (option, off by default).** Extra threshold steps after the linear fit. It is a
  heuristic that changes the objective, roughly doubles the optimisation time and is not tied to
  a measured resin threshold; level and steepness are recorded in the manifest.
- **Direct projection.** The projector tab can show the direct projection of the part (no SIRT,
  no vial compensation). It is not a "corrected vs. uncorrected" pair: the difference to the
  printed frames comes from the optimisation as well as from refraction.

#### 4. GPU acceleration is an optional component

- Taichi is no longer a required dependency. `pip install .[gpu]` (or `requirements-gpu.txt`)
  adds it to a source install, and the program build does not contain it.
- The Windows installer offers it as the optional **GPU acceleration** component (about 150 MB,
  a `gpu` folder next to the program), explained on its own page as a suggestion. It is
  pre-selected only when an NVIDIA driver is found. Silent install:
  `SpinSlicer-Setup-0.4.0.exe /SILENT /COMPONENTS="app,gpu"` (or just `app`). Run the installer
  again and choose "Custom installation" to add or remove it. The same add-on is published as
  `SpinSlicer-gpu-addon-windows-x64.zip` (unpack it as `gpu` next to `SpinSlicer.exe`).
- The add-on holds a compiled Taichi core, so it only works with the Python the program was
  built with (3.12). The release workflow runs the packaged program with the add-on and requires
  a real kernel to run.
- Without the add-on everything runs on the CPU with the same results.

#### 5. Camera control is back

The 3D view uses the earlier CAD-style navigation again (the terrain-style mode of v0.3.2
is gone):

- Left drag orbits the model freely, right or middle drag pans, and the wheel zooms.
- The orientation cube with its axis arrows is back in the corner of the view; drag it to turn
  the camera.
- A home button in the top-right corner returns the camera to the default view.

### Upgrading

Regenerate your projections: the frame rate, the codec and, with a non-default profile, the
gamma changed. Check the rotation speed in the new file name, set the projector gamma, and
check the playback chain with the test ramp before a real print.

## Русский

### Главное: гамма проектора теперь работает

Гамма проектора из профиля станка наконец **применяется к MP4, который вы отдаёте принтеру**. В v0.3.2 поле гаммы в профиле было, но экспорт его просто не учитывал. По умолчанию там по-прежнему **1.0 (линейно)**, так что с профилем по умолчанию кадры остаются такими же, как раньше.

- У большинства проекторов гамма около 2.2. Пока в профиле 1.0, кадры уходят как есть: средний серый светит заметно слабее, чем нужно, и **доза перестаёт быть линейной**. Укажите в профиле реальную гамму проектора, лучше измеренную (для этого есть тестовая рампа, о ней ниже).
- Если у вас в профиле уже стояла гамма не 1.0, раньше она ничего не делала, а теперь **изменит и кадры, и дозу** по сравнению с v0.3.2.
- PNG-кадры в папке прогона и предпросмотр на вкладке «Проектор» остаются линейными. Гамма применяется только к MP4. Если гамма не равна 1, кадры пересчитываются в дробных числах и округляются до 8 бит один раз; результат лежит в папке `projector_frames/`.

Ещё несколько отличий от v0.3.2, которые влияют на то, что получит принтер:

- Частота кадров по умолчанию теперь **30 fps** (раньше 24). 30 ровно укладывается в 60 Гц обновления проектора. При том же числе кадров изменится скорость вращения: для 360 кадров будет 5 об/мин вместо 4. Сверьтесь со скоростью в имени файла.
- MP4 теперь **H.264 с полным диапазоном яркости** (чёрный — 0, белый — 255) вместо `mp4v`, а файл называется `projection_<об/мин>rpm.mp4`.
- Разрешение кадра (`output_res`) должно быть **чётным**.

### Коротко

В v0.4.0 три режима вычислений (Авто, Экономный, Максимальный): они меняют скорость и расход памяти, но не сами кадры для печати. Расчёт на видеокарте через Taichi теперь необязательный компонент установщика. Экспорт стал H.264 и рассчитан на принтер, а на вкладке «Проектор» можно посмотреть прямую проекцию рядом с оптимизированными кадрами.

### Что нового

#### 1. Экспорт для OpenCAL

- **H.264 с полным диапазоном.** Чёрный остаётся нулевым, белый — 255. В ограниченном диапазоне фон получался 16/255, то есть примерно 6 % лишнего света на весь оборот, и пропадали 36 уровней серого. На вкладке «Проектор» диапазон можно выбрать: полный 0–255 или ограниченный 16–235. Ограниченный безопаснее, если плеер игнорирует флаг диапазона, но плеер или HDMI-выход, которые считают всё полным диапазоном, покажут чёрный как 16/255.
- **Полное разрешение.** MP4 собирается из PNG-файлов прогона, а не из предпросмотра, который уменьшен до 900 px. Скорость вращения в имени файла считается по числу кадров на диске и частоте из манифеста, с точностью до двух знаков после запятой. Понимает ли OpenCAL десятичную точку в имени файла, мы не проверяли, поэтому лучше выбирать такое число кадров, чтобы скорость вышла целой.
- **Тестовая рампа.** Кнопка сохраняет видео из серых полос от 0 до 255 (к краям полосы чаще) с выбранным диапазоном. По нему можно проверить всю цепочку от плеера до проектора, например фотометром. Пока не отмечено «С гаммой профиля», рампа линейная, так что по ней можно измерить гамму проектора с нуля. Число кадров и частота берутся от последнего прогона (для 360 кадров при 30 fps файл называется `ramp_5rpm.mp4`).

#### 2. Режимы вычислений

- **Авто, Экономный, Максимальный.**
  - *Экономный* берёт мало памяти и работает в один поток. Прямую проекцию он не строит и пишет об этом в лог.
  - *Максимальный* использует все ядра, а при установленном Taichi и подходящей видеокарте считает оптимизацию на ней: весь блок слоёв остаётся на видеокарте.
  - *Авто* выбирает режим по вашему компьютеру. Видеокарту он берёт, только если известен её объём памяти (NVIDIA, через `nvidia-smi`). Если выбрать «Максимальный» вручную, программа попробует любое доступное устройство Vulkan или Metal.
- **Кадры те же.** Экономный и Максимальный дают кадры, которые различаются не больше чем на один уровень серого, а на видеокарте и на процессоре в наших тестах они получились одинаковыми. Задание на 3DBenchy (сетка 256, 360 кадров, 505 слоёв, дозовое окно включено): Экономный — 143 с и 0,45 ГБ памяти, Максимальный на 12 ядрах — около 50 с, на RTX 4060 Ti — около 17 с. Это замеры при запуске из исходников.
- В Максимальном режиме матрица лучей сохраняется между заданиями, в Экономном освобождается.
- Если видеокарту использовать не получилось, в логе будет причина, а расчёт продолжится на процессоре. В манифест записывается, что работало на самом деле (`compute.device_used`, `compute.gpu_error`).

#### 3. Оптимизатор и проекции

- **Дозовое окно (по умолчанию выключено).** Дополнительные шаги по порогу после обычной линейной оптимизации. Это эвристика: она меняет целевую функцию, примерно вдвое увеличивает время оптимизации и не привязана к измеренному порогу смолы. Уровень и крутизна записываются в манифест.
- **Прямая проекция.** На вкладке «Проектор» можно посмотреть прямую проекцию детали, без SIRT и без поправки на колбу. Это не пара «исправленная и неисправленная»: разница с кадрами для печати складывается из оптимизации и преломления вместе.

#### 4. Ускорение на видеокарте — необязательный компонент

- Taichi больше не обязателен. Из исходников его можно добавить через `pip install .[gpu]` (или `requirements-gpu.txt`), а в саму собранную программу он не входит.
- Установщик для Windows предлагает его как необязательный компонент **«Ускорение на видеокарте»** (около 150 МБ, папка `gpu` рядом с программой). Пояснение вынесено на отдельную страницу и написано как предложение, а не инструкция. Галочка стоит заранее, только если найден драйвер NVIDIA. Тихая установка: `SpinSlicer-Setup-0.4.0.exe /SILENT /COMPONENTS="app,gpu"` (или просто `app`). Чтобы добавить или убрать компонент позже, запустите установщик снова и выберите «Выборочная установка». Тот же компонент лежит отдельно: `SpinSlicer-gpu-addon-windows-x64.zip` (распакуйте как папку `gpu` рядом с `SpinSlicer.exe`).
- В компоненте скомпилированное ядро Taichi, поэтому он работает только с той версией Python, на которой собрана программа (3.12). Релизный workflow запускает собранную программу вместе с компонентом и требует, чтобы вычислительное ядро реально выполнилось.
- Без компонента всё считается на процессоре, результат тот же.

#### 5. Вернулось удобное управление камерой

В 3D-окне снова управление как в CAD (режим «terrain» из v0.3.2 убран):

- Левая кнопка мыши свободно вращает модель, правая и средняя сдвигают, колесо приближает.
- В углу снова есть кубик ориентации со стрелками осей: за него можно вращать камеру.
- Кнопка «домой» в правом верхнем углу возвращает камеру в исходное положение.

### Если обновляетесь с v0.3.2

Пересчитайте проекции: изменились частота кадров, кодек и (если в профиле нестандартная гамма) сама гамма. Проверьте скорость вращения в новом имени файла, укажите гамму проектора и перед настоящей печатью прогоните тестовую рампу, чтобы убедиться, что вся цепочка показывает то, что нужно.
