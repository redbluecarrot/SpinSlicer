<h1 align="center">SpinSlicer</h1>

<p align="center">

SpinSlicer готовит печать для томографической объёмной аддитивной печати (VAM / CAL):
колба со смолой вращается перед проектором, и свет сотен ракурсов складывается так, что
деталь твердеет целиком сразу. SpinSlicer считает кадры проектора по STL-файлу, показывает,
что из них затвердеет, и выводит их на проектор ровно на расчётное время.

Он сделан и для учёных, работающих с CAL, и для тех, кто собирает принтер сам: каждая
настройка показывает, что она физически меняет, а каждое число берётся из модели оптики.

## Возможности

Версия 0.5.0 — см. [заметки о выпуске](docs/releases/v0.5.0.md).

- **Три шага:** *Модель* (загрузить, расставить и проверить STL), *Свет* (рассчитать
  кадры), *Печать* (вывести на проектор, сохранить MP4 или PNG). Сам принтер описывается
  один раз в разделе *Принтер*.
- **Движок FastCAL:** в круглой колбе все ракурсы оптически одинаковы, поэтому лучи
  трассируются для одного угла, а задача распадается на маленькие системы по частотам.
  В модели есть преломление (Снеллиус), поглощение (Бугер–Ламберт), потери Френеля,
  профиль пикселя и конус лучей проектора (throw ratio), поворот колбы за время кадра.
  Обычная деталь считается за секунды или минуту ([замеры](docs/validation/resources-2026-10-31.md),
  [сравнение с OSMO, PM, BCLP и классическим CAL](docs/validation/engine-judge-2026-10-31.md)).
- **Виртуальная печать:** кадры такими, какими их покажет проектор, превращаются обратно в
  дозу; затвердевшая деталь показывается в 3D рядом с моделью, с совпадением и запасом экспозиции.
- **План печати:** время и число оборотов из дозы гелеобразования, поглощения смолы и
  облучённости проектора; калибровочная печать для новой смолы.
- **Карта дозы:** доза в среднем слое и то, что затвердеет при выбранной экспозиции; её
  ползунок и есть экспозиция печати.
- **Вывод на проектор, готовый к печати:** кадры 1:1 на родном экране проектора (без
  растяжения), одна строка кадра на слой, кадр выбирается по часам (без ухода от вращения
  колбы), кадры заранее в памяти, яркость на лету и автоостановка, когда доза набрана.
- **Плавно на скромном железе:** расчёт идёт в отдельном процессе с низким приоритетом на
  всех ядрах; окно не тормозит и в простое не грузит процессор.
- **Русский и английский**, дневная и ночная темы.

## Установка и пакеты

### Готовые пакеты (GitHub Releases)

Скачайте готовые сборки со страницы [Releases](https://github.com/redbluecarrot/SpinSlicer/releases):

- **Windows 10 / 11:**
  - **Установщик:** скачайте и запустите `SpinSlicer-Setup-0.5.0.exe`
  - **Портативная версия:** скачайте `SpinSlicer-windows-x64.zip`, распакуйте и запустите `SpinSlicer.exe`
- **Arch Linux / Manjaro:**
  ```bash
  sudo pacman -U SpinSlicer-0.5.0-1-x86_64.pkg.tar.zst
  ```
- **Ubuntu / Debian / Mint:**
  ```bash
  sudo apt install ./SpinSlicer-0.5.0-amd64.deb
  ```
- **Fedora / RHEL / openSUSE:**
  ```bash
  sudo dnf install ./SpinSlicer-0.5.0-1.x86_64.rpm
  ```
- **Портативная сборка для Linux:**
  ```bash
  tar -xzf SpinSlicer-linux-x64.tar.gz
  ./SpinSlicer
  ```

### Запуск одной кнопкой (Linux)

```bash
bash spinslicer.sh --install-shortcut
```

Появится значок SpinSlicer в меню приложений и на рабочем столе. Первый запуск сам
создаст окружение `.venv` и поставит библиотеки (3–10 минут, нужен интернет, прогресс
виден в окне терминала), дальше приложение открывается сразу. Если что-то сломалось —
правый клик по значку → «Переустановить окружение». Журнал: `~/.cache/spinslicer/launcher.log`.

### Запуск из исходников

SpinSlicer поддерживает Python 3.11 и 3.12.

```bash
python -m venv .venv
# Windows
.venv\Scripts\activate
# macOS/Linux
# source .venv/bin/activate

python -m pip install -r requirements.txt -r requirements-dev.txt
python build_sirt.py
```

Запуск приложения:

```bash
python SpinSlicer.py
```

## Виртуальная печать

Принтер не нужен, чтобы проверить кадры. После генерации SpinSlicer берёт сохранённые
кадры такими, какими их покажет проектор (8 бит, гамма, контраст), считает дозу во всём
объёме с той же оптикой (преломление, поглощение, Френель, смаз вращения) и показывает,
что затвердеет: кнопка **«Виртуальная печать»** показывает затвердевшую смолу оранжевым
вместо модели (нажмите ещё раз, чтобы вернуть модель). В плане печати появляется вердикт и
совпадение с моделью, а время печати подбирается так, чтобы деталь вышла в размер; допуск
экспозиции — диапазон, в котором поверхность смещается меньше чем на пол-вокселя. Рядом с
кадрами лежат `virtual_print.stl` (открывается в любом просмотрщике STL) и
`virtual_print_slices.png` (зелёный — как надо, красный — лишнее, синий — недосвет).

Кадры CAL не похожи на фотографию детали: это «рентген» со светлыми краями и тонкими
полосами. Горизонтальные ступени в кадре там, где деталь резко меняется по высоте
(палуба, крыша); тонкие вертикальные полосы — это способ получить резкую границу дозы.
Судить о кадрах стоит по виртуальной печати, а не по их виду. У OSMO те же ступени и
полосы (см. `docs/validation/fastcal-vs-osmo.md`).

Сравнить FastCAL с OSMO и BCLP на своей модели: `python tools/compare_osmo.py model.stl --grid 128`.

## Калибровка под свою смолу и проектор

- **Экспозиция — кнопка «Калибровка».** Одна пробная печать: 9 столбиков по кругу, каждый
  получает свою дозу, от −12 % до +12 % с шагом 3 % (столбик 1 самый короткий и тусклый,
  9 — самый высокий и яркий). Напечатайте кадры со временем из плана, посмотрите, какой самый
  короткий столбик затвердел, укажите его в том же окне — слайсер поправит дозу
  гелеобразования, и время следующих печатей станет точным.
- **Гамма проектора — «тест серого»** на шаге «Печать» (строка «Настроить проектор»): видео из
  серых полос 0…255. Снимите его камерой или люксметром и подберите гамму в настройках.
- **Размытие проектора** (настройки → Проектор). Если проектор размывает соседние строки
  кадра (расфокусировка в глубокой колбе), укажите σ в миллиметрах: кадры заранее
  подрезкиваются, и после размытия доза получается та, что нужна. На модели с тонкими
  деталями при σ = 0,7 строки совпадение формы выросло с 96,0 % до 98,1 %. Завышенное
  значение вредит — оставьте 0, пока не измерили.

## Вывод на проектор

Подключите проектор вторым монитором (расширенный рабочий стол). Кнопка **«Показать на
проекторе»** выводит кадры во весь экран, пиксель в пиксель, с частотой, которая следует из
скорости вращения. Кадр выбирается по прошедшему времени, а не по счётчику таймера, так что
картинка не отстаёт от колбы даже за сотни оборотов. Засветка останавливается сама, когда
набрана доза плана × экспозиция; «Яркость проектора» ниже 100 % делает кадры тусклее и
во столько же раз удлиняет засветку. Esc на проекторе — стоп.

## Видео для проектора

«Сохранить в MP4» пишет кадры в полном разрешении (а не уменьшенный предпросмотр) кодеком
H.264 с полным диапазоном серого: чёрный остаётся 0, белый 255, все уровни сохраняются.
Нужен ffmpeg — он ставится вместе с зависимостями (`imageio-ffmpeg`) или берётся системный;
без него используется mp4v с потерями.

## STL-модели с резьбой

Загрузите гайку как обычный STL. Внутренние отверстия и
резьба по умолчанию сохраняются при растеризации сечений, в том числе при
включённой опции восстановления сетки. Шаг и глубина резьбы должны занимать
несколько вокселей при выбранном разрешении сетки: слишком мелкие элементы
невозможно надёжно представить в любом воксельном проекторе.

## Бэкенды проекций

Модуль проекций следует тем же концептуальным этапам, что Tomo и VAMToolbox:

1. вокселизация целевой геометрии;
2. генерация или оптимизация последовательности проекций по равномерно распределённым углам;
3. применение общего масштаба проекций и экспорт последовательности кадров для воспроизведения.

Бэкенд по умолчанию трассирует лучи с преломлением по Снеллиусу через пробирку
или кювету, интегрирует пересечения вокселей и затухание по Бугеру–Ламберту–Беру,
затем подбирает неотрицательные проекции относительной дозы методом SIRT.
Необязательная нативная библиотека ускоряет тот же расчёт на C++/OpenMP.
Python API также сохраняет внутренний путь Радона и необязательную совместимость с VAMToolbox.

Предпросмотр восстанавливает значения серого из экспортированных PNG и сообщает
RMSE формы относительной дозы после подгонки общего масштаба. Это не
калиброванный прогноз отверждения. Отражение Френеля, рассеяние, отклик
материала и абсолютная доза оборудования требуют дополнительной калибровки.
См. [модель и воспроизводимые проверки](docs/validation/physical-optics-v0.3.1.md).

Квадратные кюветы используют фиксированное поле проекции, равное внешней
диагонали, при каждом угле. Это значение и физический шаг пикселя записываются в
манифест; калибровка проектора должна использовать именно его. См. [коррекцию
квадратного поля и проверки покрытия углов](docs/validation/square-detector-field.md).

## Формат вывода

Каждая завершённая генерация создаёт уникальный каталог запуска:

```text
output_frames/
└── run-20260903T120000Z-a1b2c3d4/
    ├── frame_0000.png
    ├── frame_0001.png
    ├── slice_meta.json
    ├── dose_stats.txt
    ├── reconstruction_dose.npy
    ├── reconstruction_target.npy
    ├── reconstruction_preview.png
    └── manifest.json
```

`manifest.json` хранит идентификатор источника (если источник — STL), тип и
параметры модели, матрицу трансформации, бэкенд проекций, настройки смолы,
размеры кадров и `complete: true`. Репозиторий кадров проверяет число
изображений, размеры, метаданные, лимиты по байтам и статус завершения, прежде
чем проигрыватель сможет использовать запуск. Старые плоские папки с
`frame_*.png` остаются читаемыми.

## Производительность

Замеры сделаны специально на слабой машине (2 ядра 2,1 ГГц, без видеокарты); обычный
настольный процессор быстрее. Подробно — [отчёт о ресурсах](docs/validation/resources-2026-10-31.md).

| Качество | Кадров | Время | Память расчёта |
| --- | --- | --- | --- |
| Быстро (сетка 128) | 360 | ~10 с | 0,5 ГБ |
| Норма (сетка 256) | 360 | ~34 с | 1,1 ГБ |
| Точно (сетка 384) | 360 | ~69 с | 1,7 ГБ |

## Валидация и безопасность

Перед генерацией SpinSlicer проверяет конечность значений сетки, число
треугольников, границы, помещаемость в ванну, число слоёв, оценку памяти,
размеры кадров и бюджеты вывода. Длительные задачи выполняются в воркерах
`QThread` и поддерживают отмену. Каталоги вывода фиксируются только после
успешной проверки всех PNG-файлов и метаданных. Локальные пути открываются
через настольный API Qt, а не через команду оболочки.
